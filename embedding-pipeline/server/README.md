# Voyage AI (`voyage-4-lite`) Embedding Pipeline & EBS ChromaDB Server

Fault-tolerant embedding pipeline for processing large multilingual JSONL datasets into 1024-dimensional vectors generated by **Voyage AI (`voyage-4-lite`)** and stored directly on an attached AWS EBS ChromaDB instance.

---

## Architecture Overview

```text
       LOCAL MACHINE                                AWS CPU EC2
+------------------------+             +------------------------------------+
| Streaming Worker       |  HTTPS POST | FastAPI App (server/server.py)     |
| - Read .jsonl (utf-8)  | ----------->| - Voyage AI Client                  |
| - Micro-batches        |  /embed     | - Model: voyage-4-lite             |
| - Retries & Backoff    |             | - Direct Vector Storage             |
| - Checkpoint Tracker   |             | - Initialized ChromaDB on EBS      |
+------------------------+             +-----------------+------------------+
                                                         |
                                                         v
                                              +--------------------+
                                              | EBS gp3 Volume     |
                                              | /mnt/chroma        |
                                              | ChromaDB Storage   |
                                              | (kcc_docs/other)   |
                                              +--------------------+
```

---

## 1. Setting Up the Server on CPU EC2

### Step A: Format & Mount EBS Volume
Attach your EBS gp3 volume to your CPU EC2 instance, then mount it to `/mnt/chroma`:

```bash
# Verify volume device name (e.g., /dev/nvme1n1)
lsblk

# Format if new
sudo mkfs -t ext4 /dev/nvme1n1

# Mount to /mnt/chroma
sudo mkdir -p /mnt/chroma
sudo mount /dev/nvme1n1 /mnt/chroma

# Make writable
sudo chmod -R 777 /mnt/chroma

# Verify mount
df -h /mnt/chroma
```

Persist the mount across reboots by adding to `/etc/fstab`:
```text
/dev/nvme1n1 /mnt/chroma ext4 defaults,nofail 0 2
```

### Step B: Configure Voyage AI API Key
Export your Voyage AI API key:

```bash
export VOYAGE_API_KEY="your-voyage-api-key"
export VOYAGE_MODEL_ID="voyage-4-lite"
```

### Step C: Deploy & Launch Server
```bash
cd server
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# Run FastAPI server
export CHROMA_PATH="/mnt/chroma"
python3 server.py
```

Verify server health:
```bash
curl http://localhost:8000/health
```

## 2. Running the Client Locally

Run the local worker to stream your `.jsonl` files to the CPU EC2 server.

### Setup
```bash
cd client
python -m venv venv
# Windows: venv\Scripts\activate
# Linux/Mac: source venv/bin/activate
pip install -r requirements.txt
```

### Execution
```bash
export EMBEDDING_API_URL="http://<YOUR-EC2-PUBLIC-IP>:8000"

python worker.py --input ../data
```

## 3. Server Endpoints

| Endpoint | Method | Description |
| :--- | :--- | :--- |
| `/health` | `GET` | Returns status (`ok`), provider (`Voyage AI`), model (`voyage-4-lite`), dimensions, chroma path, and document count per collection (`kcc_docs` and `other_docs`). |
| `/stats` | `GET` | Total requests processed, total chunks embedded, average latency. |
| `/embed` | `POST` | Micro-batch embedding endpoint. Invokes Voyage AI `voyage-4-lite` and stores vectors in ChromaDB on EBS. |
