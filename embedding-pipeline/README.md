# AWS Bedrock Titan V2 Embedding Pipeline & EBS ChromaDB Server

Fault-tolerant embedding pipeline for processing large multilingual JSONL datasets into 1024-dimensional vectors generated by **AWS Bedrock Amazon Titan Text Embeddings V2 (`amazon.titan-embed-text-v2:0`)** and stored directly on an attached AWS EBS ChromaDB instance.

---

## Architecture Overview

```text
       LOCAL MACHINE                                AWS CPU EC2
+------------------------+             +------------------------------------+
| Streaming Worker       |  HTTPS POST | FastAPI App (server/server.py)     |
| - Read .jsonl (utf-8)  | ----------->| - boto3 AWS Bedrock Runtime Client |
| - Micro-batches        |  /embed     | - Model: titan-embed-text-v2:0     |
| - Retries & Backoff    |             | - Parallel ThreadPool Execution    |
| - Checkpoint Tracker   |             | - Initialized ChromaDB on EBS      |
+------------------------+             +-----------------+------------------+
                                                         |
                                                         v
                                              +--------------------+
                                              | EBS gp3 Volume     |
                                              | /mnt/chroma        |
                                              | ChromaDB Storage   |
                                              | (kcc_docs/other)   |
                                              +--------------------+
```

---

## 1. Setting Up the Server on CPU EC2

### Step A: Format & Mount EBS Volume
Attach your EBS gp3 volume to your CPU EC2 instance, then mount it to `/mnt/chroma`:

```bash
# Verify volume device name (e.g., /dev/nvme1n1)
lsblk

# Format if new
sudo mkfs -t ext4 /dev/nvme1n1

# Mount to /mnt/chroma
sudo mkdir -p /mnt/chroma
sudo mount /dev/nvme1n1 /mnt/chroma

# Make writable
sudo chmod -R 777 /mnt/chroma

# Verify mount
df -h /mnt/chroma
```

Persist the mount across reboots by adding to `/etc/fstab`:
```text
/dev/nvme1n1 /mnt/chroma ext4 defaults,nofail 0 2
```

### Step B: Configure AWS Credentials for Bedrock
Ensure your EC2 instance has an IAM Role attached with Bedrock permissions (`bedrock:InvokeModel`), or set environment variables:

```bash
export AWS_REGION="us-east-1"
# Optional if using IAM access keys instead of IAM Role:
# export AWS_ACCESS_KEY_ID="your-access-key-id"
# export AWS_SECRET_ACCESS_KEY="your-secret-access-key"
```

### Step C: Deploy & Launch Server
```bash
cd server
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# Run FastAPI server
export CHROMA_PATH="/mnt/chroma"
export BEDROCK_MODEL_ID="amazon.titan-embed-text-v2:0"
python3 server.py
```

Verify server health:
```bash
curl http://localhost:8000/health
```

## 2. Running the Client Locally

Run the local worker to stream your `.jsonl` files to the CPU EC2 server.

### Setup
```bash
cd client
python -m venv venv
# Windows: venv\Scripts\activate
# Linux/Mac: source venv/bin/activate
pip install -r requirements.txt
```

### Execution
```bash
export EMBEDDING_API_URL="http://<YOUR-EC2-PUBLIC-IP>:8000"

python worker.py --input ../data
```

## 3. Server Endpoints

| Endpoint | Method | Description |
| :--- | :--- | :--- |
| `/health` | `GET` | Returns status (`ok`), provider (`AWS Bedrock`), model (`amazon.titan-embed-text-v2:0`), region, and document count per collection (`kcc_docs` and `other_docs`). |
| `/stats` | `GET` | Total requests processed, total chunks embedded, average latency. |
| `/embed` | `POST` | Micro-batch embedding endpoint. Invokes Bedrock Titan V2 and stores vectors in ChromaDB on EBS. |
